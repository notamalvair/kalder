# Исправления frontend: пять этапов

1. **Готово:** единая проверка домена/email, нормализация URL, ошибки у полей, ARIA-связи и фокус на первом ошибочном поле. Поддерживаются домены, IDN и обычные HTTP(S)-пути; IP-адреса, локальные имена, собственные порты и URL с учётными данными отклоняются. Это клиентская подсказка; серверная проверка DNS/IP остаётся обязательной.
2. **Готово:** восстановление статуса заявки после обновления страницы через sessionStorage без хранения email. Сохраняются только ID и время, срок — семь дней. Повторный POST при восстановлении не выполняется. При 404 сохранённый ID удаляется с пояснением; после завершения можно явно начать новую заявку. Заблокированное хранилище не ломает форму.
3. **Далее:** страница 404 с понятной навигацией.
4. **Ожидает:** мобильное меню и навигация с клавиатуры.
5. **Ожидает:** локальные шрифты/изображения и итоговая проверка.

Проверки этапов: `node --test backend/*.test.mjs` (34 теста, Node 24), `npm run typecheck`, `npm run build -- --outDir .runtime/build`, `python backend/browser_check.py` (Chromium/Playwright). Браузерный тест проверяет сообщения, фокус, полный путь до локального письма, восстановление после reload без повторного POST и обработку отсутствующей заявки; реальную почту не отправляет.
