# KALDER — демонстрация через nginx

Для домашней проверки новой версии: [Docker Compose: сайт + backend](docs/HOME_SETUP.md).

## Новый backend Website Check

Исходники дополнены API и очередью формирования отчётов. Запуск для разработки — в двух терминалах из корня:

```bash
node backend/server.mjs
npm run dev -- --host 127.0.0.1
```

Нужна Node.js 22.13+ с `node:sqlite` (проверено на 24.19.0), зависимости frontend устанавливаются через `npm ci`. По умолчанию письма сохраняются локально, без реальной отправки. Форма принимает домен и email. [Инструкции backend, проверки и ограничения](backend/README.md).

**Ниже описана прежняя демонстрация из архива:** включённый `dist/` сохранён без изменения; nginx/Docker запускает именно его, без нового backend. Актуальный frontend собирается отдельно в `.runtime/build`.

Это рабочий фронтенд Variant B. Сборка `dist/` уже включена: Node.js для показа не нужен.

## Запуск

Нужен установленный nginx **или** запущенный Docker Desktop / Docker Engine с Compose v2. Первый Docker-запуск скачивает образ и требует интернет.

- **Windows:** установите Git for Windows и Docker Desktop, запустите Docker Desktop, дважды нажмите `START_WINDOWS.cmd`.
- **macOS:** nginx или Docker Desktop, затем `START.command`. Если система запрещает запуск скачанного файла, выполните в Terminal `bash start.sh` из этой папки.
- **Linux:** из этой папки выполните `bash start.sh`.

Откроется http://localhost:8080. Если браузер не открылся, откройте адрес вручную.
Остановка: `bash start.sh stop`. Статус: `bash start.sh status`.
Другой порт: `PORT=8090 bash start.sh`. При смене порта сначала остановите прежний запуск.
По умолчанию доступ только с этого компьютера. Для удалённого показа используйте демонстрацию экрана.

## Что показывать

Откройте `docs/CLOSER_DE.html`: там сценарий на немецком на 7 минут.
Путь сайта: главная → Website Check → Kontakt → Leistungen → Projekte.
Форма проверяет ввод, но не отправляет его. Автоматического сканирования сайтов нет.
Impressum/Datenschutz — заглушки, проекты — концепты. Фото и шрифты могут требовать интернет.

## Карта исходников

| Путь | Что менять |
|---|---|
| `src/pages/` | Страницы и форма контакта |
| `src/components/` | Блоки сайта и навигация |
| `src/config/site.ts` | Название, email, данные компании |
| `src/lib/analytics.ts` | События, пока без подключённого сервиса |
| `src/index.css` | Цвета, типографика, общие стили |
| `src/App.tsx` | Маршруты |
| `nginx/` | Конфигурация nginx и типы файлов |
| `docs/` | Гид клоузера и заметки по A/B |
| `dist/` | Готовая сборка; не редактировать вручную |
| `.runtime/` | Локальные PID и журналы запуска; не передавать |

После изменения исходников: Node.js 22 LTS, затем `bash start.sh build`.
Для разработки: `npm ci`, `npm run dev`. Сборка: `npm run typecheck && npm run build`.
При Docker-запуске после пересборки достаточно обновить страницу; при смене конфигурации — stop/start.
Системная конфигурация nginx не меняется, sudo не нужен. Используется отдельный экземпляр на высоком порту.

## Границы готовности

Подходит для внутренней демонстрации. Публичный запуск требует реальных реквизитов, согласованных контактов, отправки формы и проверки контента. `noindex` в демо намеренный; это не защита доступа.
